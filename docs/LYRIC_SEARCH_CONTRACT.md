# Lyric search and reader recovery

`POST /api/music-romanize` accepts two additional authenticated actions. Existing recording-bound requests and response contracts stay intact. Search responses are independent source capsules, never verified recording bindings or Song Library documents. Both actions use the existing app session and rate limit, perform no generation, and return version 1 JSON.

Search request: `{ "action": "search_lyrics", "query": "父亲 筷子兄弟", "hints": { "title": "父亲", "artist": "筷子兄弟", "artists": ["筷子兄弟"], "album": "父亲", "duration": 280.289 } }`.

Hints are optional. When supplied, title and artist are required; album, complete artists, duration in seconds, catalogID and spotifyItemID are optional. Exact item hints only maintain reviewed negative language/content exclusions; they do not grant recording equivalence. Queries are 1–500 characters. Unknown fields fail with 400. An optional unique `providers` array enables `lrclib`, `netease`, and `kugou`. Omission preserves the original LRCLIB/NetEase search. Discovery never changes automatic provider matching.

Search response: `{ "version": 1, "candidates": [...], "unavailable": ["netease"] }`. Up to 20 candidates are ranked by normalized title/artist similarity, duration proximity, album and availability of readable words. Duration affects rank without discarding words. `namesMatch` requires full normalized title/contributor agreement; `durationMatches` records the separate three-second criterion. Neither establishes verified timing. Provider failures preserve other results; all-provider failure returns 502.

Candidate fields: `provider` (lrclib, netease, or kugou), `itemID` (opaque decimal string), `title`, `artist`, optional `artists`, `album`, `duration`, `lines`, plus search-only `namesMatch`, `durationMatches`, `score`. Lines contain `text`, an optional source `timestamp` in seconds, and optional validated `vocalTiming` using the existing UTF-16 cue contract. Available NetEase YRC is retained; malformed optional cues are dropped without discarding readable words. Kugou currently supplies line timing only. LRCLIB searches already include words; other providers normally require preview. Up to 250 lines, 4,000 characters each, 180 KB per transcription and 500 KB of embedded search data are retained. Credit normalization and reviewed source exclusions still apply.

Preview request: `{ "action": "preview_lyrics", "provider": "netease", "itemID": "123", "hints": {...}, "query": "Source title Source artist" }`. Response: `{ "version": 1, "candidate": {...} }`. Query is required for Kugou, where fixed-provider rediscovery reacquires a short-lived download capability for the exact item; it is optional elsewhere. Only allowlisted providers and decimal IDs route to fixed provider origins; client URLs and capabilities are never accepted or returned. Source metadata and words are fetched independently of caller labels. Empty, wrong-ID or unusable sources return 404; transport failure returns 502.

A client can show matching-name candidates as explicitly unverified, untimed suggestions after ordinary recording lookup fails. Manual selection/import pins an exact local recording and immutable source revision. Alternative words never change playback ID or fabricate a recording binding. Timing remains a separate explicit decision. Automatic verified acquisition keeps all existing identity checks.

## Explicit selected-source learning

Authenticated `POST /api/song-library` action `selected_source` accepts only `provider`, `itemID`, optional `query` (required for Kugou), and `expectedTextHash`. The server independently fetches the provider and requires a SHA-256 of the exact ordered UTF-8 original rows: prefix `selected-source-text-1\n`, then each row's decimal byte length, `:`, and its unmodified bytes. Repeated rows and normalization differences matter. A changed transcript returns `selected_source_changed`; registration performs no model work or allowance reservation.

The version-1 ready reply contains a source-only immutable document and `selectedSource: { version: 1, provider, itemID, textHash }`. Policy is `selected-lyrics-learning-1`. Provider labels are retained exactly; public learning rows are untimed, while source timing and deterministic readings contribute to the immutable source hash. Internal capsules and model context are never exposed. No playback/catalog request, alias, recording head, or automatic cache entry is created. The playback-to-source attachment stays on-device.

Each account must independently register a document before accessing its translations, pronunciation, explanation, or job status. Access is checked before cached content and pending-job recovery; new translation/Study reservations recheck it transactionally with the live account. New selected-source generation always requires explicit `allowGeneration: true`, including beta/unlimited access. Ready reuse and already authorized jobs need no second reservation. Deleting an account removes its private access links while preserving shared source documents. Older sources and their saved learning remain available to previously registered accounts; choosing a replacement does not erase them. Selected-source reuse has its own semantic namespace and never bridges into automatic Apple/Spotify documents or pending jobs.
