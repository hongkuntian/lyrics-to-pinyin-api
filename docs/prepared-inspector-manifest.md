# Native inspector enumeration v1

`prepared-inspector-manifest-v1.json` is a structural example with placeholder hashes, not publishable content. `requests` contains **every** distinct canonical request to be offered by the inspector across original + all five translated layers and all five explanation languages. Each entry has `{kind,selector}`. Translation selector includes canonical target and accepted revisionID. Batch selector uses current `explain_line` request fields (`contractVersion:1`, `studyText`, `manifest`, `explanationLanguage`) plus `recipe:'study-line-1'`. Singleton selector uses `contractVersion:2`, `studyText`, `selection`, `explanationLanguage`, plus recipe (`study-text-1` for English, `study-text-2` for other explanation languages). Deduplicate identical actions (e.g. one-grapheme word and character) by exact canonical selector.

Keep original `studyText.revisionID=documentID` with no translation context. Translated `studyText` includes target+accepted translation revision only; never `contextTranslation`. For a genuine no-translation direction, backend supplies an accepted identity translation with its own target/revision and exact original text. This is explicit in the translation artifact; native must use its server revision, never construct one.

Words use the real native inspector's legal spans, batched in groups of <=32 within the same occurrence, nonoverlapping and sorted. Whole line and offered Han characters use singleton requests; max 80 graphemes per existing API selection. Source ID distinguishes repeated occurrences. Text hashes use the existing SHA-256 of selected grapheme substring. The preparation compiler validates selectors with existing `lineSelections` / `selectionV2`, and derives required artifact IDs from all requests. Publication requires a parity receipt referencing the exact manifest artifact hash produced from this native enumeration, not Intl tokenization alone.

Grant descriptors are `{id,kind,selector}`. Artifact content uses existing public batch/explanation/translation/document shapes. A manifest artifact contains the full enumeration so the app can map a request to its exact prepared artifact before inspecting. The backend candidate also exposes descriptor selectors in each grant. Every artifact request must send editionID+generation+use and, for play, the same exact variant. No arbitrary study text or document identity is accepted on listener read APIs.
