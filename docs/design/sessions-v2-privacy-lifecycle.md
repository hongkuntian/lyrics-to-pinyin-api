The sole module export is `createPrivacyLifecycle({db,coordinatorEnvironment})`. `db` supplies the existing same-client `transaction(fn)` and `query` adapter. Factory construction validates and captures configuration without IO. The configured coordinator is the one trusted database-wide namespace; no method accepts a request environment, clock, callback, authorization boolean, action name, column or selector object. Configuring inconsistent coordinators against the same database is unsupported; deployment fingerprinting belongs to Root. The frozen returned object is trusted infrastructure and must never be exposed through an arbitrary request dispatcher.

## Source evidence, global coalescing and repair

Preparation requires a live preimage of its named source class; already revoked/disabled sources are repair failures. It samples `clock_timestamp()` after Root's anchors and before intentional mutation. Persistence rereads the exact source projection and checks its closed postcondition: token revoked with same owner/deadline; key revoked or moved; guest/Apple disabled without incidental access-kind change; or Apple epoch exactly old+1. Expiry has no intentional mutation and requires the same token/deadline still expired. No absent-source or arbitrary `negative:true` success path exists.

Dependency payloads are exactly 031's `{version:2,environment,selector,cursor,invalidatedAtMS}` and job keys are `privacy-dependency:<jobUUID>`. All execution/reference fields are null. The account INSERT names only its permitted `environment,job_id,job_key,kind,payload,created_at_ms,due_at_ms,retry_until_ms` columns, uses `ON CONFLICT DO NOTHING`, and then requires exactly one unfinished exact-selector row whose timestamp is no later than incoming evidence. Missing, malformed, concurrently published, or later-time conflicts refuse. Account never UPDATEs outbox. Current and worst global cursor encodings go through the completed codec and SQL constraints.

Runtime timestamp repair accepts only a genuine producer plan after its negative postimage. The exact pending/dead row's observed payload, state, epoch and null nonce/lease fence its last-position CAS. It applies `LEAST`, resets cursor only for earlier evidence, and leaves creation/retry/attempt/dead completion metadata intact. Claimed rows require finishing/retrying their fenced owner first. This method cannot accept an arbitrary historical timestamp. Recovery of a lost historical record needs authentic external retained evidence and a separately reviewed Root repair; it is unavailable here.

An indexed sweep uses retained persona expiry as an exact independent proof. For revoked/missing/moved public sources, it needs authentic matching durable dependency evidence, including a valid era at or after persona creation. Missing revocation time, a later incarnation behind an earlier T0, or an ambiguous full evidence page fails closed. The bounded evidence lookup refuses at 100 matching historical jobs rather than discard an unexamined suffix. This can require Root repair even when a relevant event exists beyond that page; it is a conservative availability limit, not permission to invent time. No source expiry, withdrawal date or responsibility deadline is replaced with processing time.

## Claim and dependency transaction boundaries

Claims select at most one due pending or expired claimed job with `FOR UPDATE SKIP LOCKED`; transaction touches only clocks/outbox. Attempt count stays <=10, claim epoch increments exactly, a cryptographic nonce hash is generated internally, lease is <=30 seconds and <=original retry deadline, and retry window remains <=original job creation+24h. Saturated/expired work becomes dead and is kept. No DELETE/age cleanup path exists. Dead is a retained obligation, not a successful queue delivery.

The instance-owned claim snapshot binds kind, exact environment/job/key, closed observed payload/cursor, original creation/retry, attempt, epoch and nonce. Processing is a separate transaction after claim commit. Forged/cross-instance handles refuse before SQL. Job-last locking rechecks actual state, payload, epoch/nonce and fresh DB lease/retry time; final progress checks fresh DB time again. Successful use consumes the handle. Failed processing rolls back and leaves the same durable claim for exact retry or later lease reclaim; it does not steal or reset a claim.

For each dependency kind, the module has actual separate first and successor SQL with 031's entire dependency-prefixed keyset, equality prefix, literal controller/status predicate and `COLLATE "C"` environment ordering. Indexed-sweep uses its own complete environment/UUID tuple. No optional-cursor OR, caller-selected column, suffix-only dependency seek or request-environment filter is used. All matching namespaces participate.

Nonlocking discovery selects <=100 personas. It chooses a complete ordered candidate prefix for which the full union of controller/original users plus current token/key owners, token digests and keys fits 64 per category. No selected candidate loses a required identity. It locks users `NO KEY UPDATE` in UTF-8/C order, then tokens, all keys, then personas ordered environment/UUID. Current public rows and exact persona tuples must match discovery; new/changed earlier identity refuses rather than append a lock. It has no session requirement or positive authentication assertion. The operation mutates no guard, connection or provider state, so it takes no fabricated guard scope. Real writer guard fences remain Root's actual earlier-scope work.

After the exact job lock last, each actual negative dependency/epoch is rechecked with fresh DB time. A transferred live Apple persona is absent from old guest selectors after its real controller/dependency change. Invalid guests and Apple controllers use the earliest proven source event and exact retained expiry. A persona created after that evidence refuses instead of being scrubbed under a pre-incarnation time. Live expected generation CAS increments once, writes original withdrawal and <=24h due, mirrors the exact 41-byte `p2:<jobUUID>:<phaseCode>` marker, INSERTs its typed scrub payload/job, and advances only the last processed dependency key in the same transaction. Failure in any part rolls back all parts. Duplicate delivery does not increment a terminal generation.

A nonempty batch yields pending. A later empty successor transaction rechecks the complete live selector range from its beginning under the same source/new-retention anchors, with outbox locked last. A matching row behind the cursor resets the dependency cursor to null; it does not publish. Only no remaining matching live rows permits dependency publication. This is handoff of negative responsibility, not physical scrub completion. Sweep publication means end of one rotating pass; `ensureSweep()` can then insert a new null-cursor pass. Valid rows beyond the first page are visited; no invocation drains the history.

Missing/deleted targeted source anchors cannot support safe final-publication serialization in this representation. The engine refuses even for an empty final range instead of guessing a former owner. Root must keep the real source/new-retention anchors until responsibility is handed off or provide a reviewed stable-anchor repair. Root's real first-retention/reactivation/transfer methods must hold those same user/token/key/controller anchors and refuse every exact matching pending/claimed/dead successor selector globally. That consumer check is Root-owned and is not supplied as an unused permit API here. Neither a published predecessor nor the absence of a job proves current liveness/consent.

A dead dependency can be replaced only before its original retry window closes. The replacement transaction holds the actual source anchors, checks the exact dead observation/job last, and inserts its bounded successor atomically with predecessor publication. It keeps the original payload, creation and retry deadline; no in-place reset manufactures timeliness. Expired retry windows and dead scrub recovery remain explicit Root repair debt. There is no automatic successor after the deadline and no destructive expiry.

## Scrub phases and exact postimages

Every scrub invocation first discovers the exact terminal persona, phase targets and all earlier user/token/key identities, locks those anchors, then persona, grant scopes or rooms, exact event/receipt/asset rows, and the job last. It compares expected persona generation, status `withdrawn`, original withdrawal/due, compact phase marker, observed rows and full claim payload/cursor. Target generation rights are only terminal-1 or the exact retained one-time private transfer bridge; there is no blanket <=generation acceptance. Every successful phase changes persona marker and job payload/cursor together. Every target mutation checks its exact observed actor/side/generation/preimage. Missing or incompatible state refuses atomically.
