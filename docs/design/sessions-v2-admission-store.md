# Sessions V2 SQL admission service

This disabled SQL service composes the approved [admission reducer](sessions-v2-admission.md), [receipt gateway](sessions-v2-receipt-store.md) and [storage contract](sessions-v2-storage-schema.md). Authority is the complete R5 architecture SHA-256 `7d4bd6a6d6b8b6c7be2044a2be61c0fd7841c1ba77d9e982bd592e7d1a24f049`. It executes parameterized SQL on the receipt gateway's transaction connection. There is no HTTP adapter, capability enablement, production auth/privacy composition, migration registration/application, provider operation or deployment.

## Storage representation

The maintained migration 030 includes an independent `returning_grants.cooldown_until_ms safe_uint NOT NULL DEFAULT 0`, inside the existing <=1,024-byte logical row bound and unique `(environment,host_install_scope,pair_digest)` lookup. Denying a pending request while a remembered grant remains active preserves its generation/status and sets a 60-second cooldown, including across another room with the same host installation. `revoked_at_ms` cannot represent this: active rows require it null, and Forget remains distinct. No per-denial row or host-history scan is introduced. Runtime can update this scalar; account-role grant redaction cannot. The service refuses without domain/receipt writes if required representation is missing.

There remain exactly eight V2 relations. Composite room/environment FKs, the <=512-byte event payload bound, indexes and role grants are unchanged. No private event-authority sidecar, ninth relation or extra PII budget is introduced. Retained worker proposals and correction evidence stay in ignored artifacts.

Terminal persistence uses existing event columns for environment, session, request UUID (`event_id`), server time, requester persona and privacy generation. The **entire event payload**, measured as PostgreSQL `jsonb::text`, contains only `{version:2,status,pairDigest}` plus `{memberID,memberLeaseVersion}` for admission and `decidedByMemberID` for an explicit decision. The maximum admitted payload, with full UUIDs, 64-digit digest and maximum safe-integer lease, is **271 bytes**, below the unchanged 512-byte limit. Null references are omitted. The payload duplicates no event metadata; the terminal event stores no installation tuple, credentials or profile/name/photo data. There is no new terminal array or ninth relation. Public delivery must still apply the architecture's current privacy/ACL projection to these references.

The service uses the server request UUID as the terminal event UUID, preserving targeted `(environment,event_id)` uniqueness and lookup. Existing indexed actor-persona and privacy-persona primary keys locate canonical authority. Full in-memory reducer facts are reconstructed only under already prepared/held SQL scopes through the mandatory typed resolver below. Missing or scrubbed authority refuses; the retained event UUID remains the first-winner marker. Root's privacy lifecycle must preserve that marker through the active room's lifecycle while redacting persona/payload as required. It must not delete the marker early or repurpose the event UUID. Terminal pending-request PII still withdraws immediately and scrubs within 24 hours; existing actor/room indexes and account event-redaction grants are sufficient for this representation. No extra scrub index or grant is required.

## Closed internal API

`createAdmissionStore(options)` returns only frozen `{execute}`. The options are the receipt gateway's key rings, active versions, environment, database and clocks, plus four **mandatory, construction-time trusted functions**: `lockAuthorization`, `resolveFacts`, `resolveTerminalAuthority`, and `revalidateFacts`. Missing functions fail construction. A transaction wrapper must commit immediately after callback success, roll back on every exception, never rerun its callback independently, and use bounded trusted SQL deadlines. No callback, actor, role, facts, environment or transaction can be selected through `execute`.

```js
await service.execute({authentication, rawCommand, creationTicket?});
```

`authentication` is prior trusted app authentication, never an HTTP body object. All client-derived intention data enters through bounded **raw JSON text**. The existing parser rejects duplicate aliases, unsafe/source-invalid numbers, unknown keys, preparsed objects and over-16-KiB UTF-8 before reflection/parse. Input objects themselves reject proxies, accessors and extra fields. Clocks default to the existing receipt gateway's current database wall clock. The returned value is its committed redacted receipt `{version,sessionID,commandID,status,result,replayed}`. An equal retry never calls either fact resolver or replays grants, state changes, events or outbox work. Current auth/privacy must still permit that saved result.

Local intention forms are deliberately separate from the unchanged shared core V2 schema:

| Action | Envelope / expected | Payload |
| --- | --- | --- |
| `create` | `{version:2,action,expected:{},payload}`; IDs come only from the existing verified creation ticket | `{provider:'appleMusic'|'spotify',storefront,title,profileReference,profileRevision,roomConsentRevision,initialIntent:'none'}` |
| `admission.request` | Existing local admission envelope, expected `{}` | Existing resolve/profile/consent fields |
| `admission.decide` / `admission.cancel` | Expected `{requestVersion}` | Existing request UUID and decision where applicable |
| `settings.update` | Expected `{settingsRevision}` | Strict nonempty title/Ask/Take turns patch, with existing title validation |
| `leave` | Expected `{memberLeaseVersion}` captured by that intention | `{}` |
| `remembered.forget` | Expected `{grantGeneration}` | `{grantID}`; original host only |
| `admission.expire` | Expected `{}` | `{}`; internal lifecycle authority only |
| `admission.remove` | Expected `{memberLeaseVersion}` | `{memberID,reason:'authorization_withdrawn'|'participation_closed'}`; internal lifecycle authority only |

Creation accepts **only no-audio `initialIntent:'none'`**. It stores Ask=true, Take turns=false, profile/consent references, one original host, exact invitation/code digests, an eight-hour-or-shorter immutable expiry, empty occurrences/visits, epoch zero, reserved End capacity and atomic expiry/wake jobs. It grants no playback or output ownership. Restart/adoption/host authorizations/End are outside this registry. Storefront is a bounded opaque ASCII identifier, not catalog/provider availability proof.

The service derives the actor lease from the stored exact active installation/persona membership. Leave additionally compares the intention's captured lease version; it never upgrades an old Leave to the rejoined lease. Host settings/Forget require the original hosting installation. Any active member can decide a pending request. The original host, provider, queue/visit arrays and their scalars, transport revisions, output guards and execution state are preserved by admission updates. The settings flag persists here; cross-feature queue/fairness integration remains Root-owned.

## Trusted transaction authorization and fact resolution

`lockAuthorization(args)` is compatible with the existing receipt hook: same `{tx,authentication,environment,command,bindingKeyManifest}`, same receipt permit fields and `revalidate` phases. It must actually compare the HMAC key manifest with immutable configured secrets, lock/recheck current app session/credential/user/key ownership/bundle/audience/attestation environment, and enforce action/read/privacy rights. Returning structurally plausible strings or a hash echo is insufficient. It additionally returns this **closed** `admissionContext`:

```js
{
  version:1, environment, mode:'member'|'lifecycle',
  install, persona, // exact approved reducer shapes; both null for lifecycle
  notAfterMS,      // <= receipt permit deadline AND every prepared fact deadline
  knownKeys, knownPersonas, hostScopes, grantPairs, grantIDs
}
```

The five scope arrays are sorted, unique, bounded and server prepared. Keys/personas/pair digests/grant IDs have at most 335 entries; host scopes at most four. Scope declaration does **not** acquire a lock or prove authentication. The hook must lock the actual rows, including already existing matching grant rows, before returning. Missing/discovered earlier scopes abort: the service checks declarations and never goes back to lock an earlier identity/persona/grant scope from inside a room mutation. The exclusive authenticated key anchor and host key/scope absence anchor serialize all cooperating receipt/grant/admission/Forget/lifecycle writers. Known pair digests protect absent-row grant creation as well as existing rows. A PGlite fixture's broad small scope set is not a production discovery implementation.

Preserve the approved order: existing settings/identity anchors; sorted users/tokens; sorted exact App Attest keys including host grant anchor; sorted connections; output guards; personas; host grant scopes/rows; room; deterministic receipt/event/outbox rows. Resolver SQL after room locking may read already locked rows and write already owned state; it must not obtain missing earlier locks, use a second pool/transaction, perform network/provider/catalog/image work, or schedule after-commit effects. Scope preparation can use bounded untrusted preflight references, but every scope and fact must be revalidated in this transaction. Stale discovery refuses rather than retrying with invented facts. Receipt gateway serialization/deadlock retries retain the same immutable intent and use a new correctly prepared transaction.

`notAfterMS` is a prepared minimum, including actual auth and referenced guest credential deadlines, current profile/resolve authority and any positive-work permit deadline. The service binds that deadline into the receipt gateway's final fresh-clock check. Resolved positive-work/resolve deadlines must cover it. This closes deadline crossings after the final fact hook: a fixture crossing the deadline during receipt INSERT rolls the whole transaction back. Do not substitute a rolling/default credential deadline. Replay gets a newly current read authorization and does not renew the original resolve or repeat admission.

`resolveFacts({tx,command,room,nowMS,authorization})` is required on every **new** execution. It returns one frozen-by-service, strictly validated closed shape:

| Kind | Required fields beyond `kind` |
| --- | --- |
| `create` | `antiAbuse, profile, hostScope, memberID, inviteDigest, codeDigest, expiresAtMS` |
| `request` | `antiAbuse, profile, resolve, pair, hmacKeyVersion, policyRevision, grantID, requestID, memberID` |
| `pair` | `antiAbuse, pair, hmacKeyVersion, policyRevision, grantID, memberID` |
| `plain` | Optional `antiAbuse`; required for positive settings work |

`profile`, `resolve`, and `pair` are the exact approved reducer fact shapes. The resolver verifies current profile/consent and resolve MAC/audience/invite generation, stable environment-scoped HMAC pair/key-version continuity, grant policy and server IDs; request/member/grant IDs never come from caller facts. Existing member IDs are reused on rejoin. A decision resolves the pending request's verified requester/pair, not the deciding client's identity. Terminal losers may return `plain`; no new grant authority is required to return a retained winner. The service loads actual grant/cooldown rows with the indexed pair key, validates known current persona generations/status, and constructs the reducer's grant fact from **SQL**, rather than trusting a supplied `active` string. Existing grant IDs/key versions must match resolved authority. Key-ring rotation continuity beyond this exact resolved pair/version remains mandatory trusted work; a missing/mismatched version refuses.

`antiAbuse` is `{status:'allowed'|'denied'|'unavailable',notAfterMS}`. It must represent real bounded deployment/install/principal/room/pair permits, including 3/min/install and 10/hour/host-pair admission limits, with enrollment/resolve circuits and cleanup readiness. There is no permissive default or replacement in-memory limiter. Denied/unavailable permits refuse before a receipt or domain mutation. Cooldown rate refusals also allocate no receipt. Reserved terminal settlement does not depend on this external permit. The fixture deliberately supplies synthetic allowed permits to exercise DB invariants; it does not implement service abuse controls.

`revalidateFacts({tx,command,room,nowMS,authorization,facts,terminalAuthority,phase})` must return exactly true only after same-connection current reference checks. It runs before mutation and again at the gateway's commit phase, alongside the receipt auth hook. Recheck every relevant actor/requester/host/grant side/controller/generation/GuestLive dependency, consent, profile, resolve/pair/policy authority and positive-work permit. It may read only already held rows, acquire no earlier locks and mutate nothing. False/malformed/missing answers fail closed and roll back; fixture failures prove atomic refusal, not credential privacy. Internal lifecycle permits are separately authenticated/authorized server authority, never a request-selected role. Only an explicitly authorized removal target or due internal expiry target may close active participation using a withdrawn generation. Already closed `left`/`removed` rows are historical references: their canonical rows/scopes must still exist and their generations must not regress, but they supply no live authority and cannot block another member's reserved Leave/removal merely because they are withdrawn. Active members and pending requests continue to require live, exact generations outside that explicit lifecycle closure. Rejoin checks the active postimage; terminal hydration independently requires current live authority. The trusted revalidation hook must make the same distinction between historical references and current authority dependencies. No old generation is revived or scrubbed by this service; Root still owns immediate projection withdrawal and timely scrubbing.

### Typed terminal reconstruction hook

`resolveTerminalAuthority({tx,command,room,nowMS,authorization,reference})` is called only for a new decide/cancel whose target is no longer pending and whose exact indexed terminal event exists. `room` is the gateway's immutable locked row. `reference` is frozen and closed:

```js
{version:1,environment,sessionID,requestID,persona,atMS,
 originalPrincipalID,originalKeyID,pairDigest,status,memberID,memberLeaseVersion,decidedByMemberID}
```

The service obtains origin principal/key and current status/generation from the canonical referenced `privacy_personas` row on this transaction. Declared `knownPersonas` and `knownKeys` must already contain it; discovery after room lock aborts and never adds earlier locks. It then requires one of these closed typed answers:

```js
{version:1,status:'available',environment,sessionID,requestID,persona,install,notAfterMS}
{version:1,status:'withdrawn'}
{version:1,status:'unavailable'}
```

An available answer must resolve the **exact immutable original installation metadata** from existing App Attest records/prepared server authority, never the current deciding actor, current key owner after a move, an inferred audience/bundle, truncation, a default or trusted-looking flags. Its complete installation is the approved `{principalID,keyID,bundleID,audience,attestEnvironment}` shape. The service compares original principal/key with the canonical persona, exact persona generation, environment/session/request bindings and all structural/width/deadline bounds. The resolver must independently validate original immutable key metadata, pair/key continuity, current requester privacy controller/GuestLive/credential/policy and historical member/lease provenance, using only already held scopes on `tx`. No network, second transaction, new earlier locks or reconstructed identity from a receipt/member/grant substitute is permitted. Missing immutable metadata returns unavailable, effective withdrawal returns withdrawn. Current persona withdrawal/generation mismatch is also checked directly in SQL.

The resolved minimum `notAfterMS` must be strictly current and cover `admissionContext.notAfterMS`; the precomputed admission deadline must already be no later than every prepared terminal dependency. A late-discovered earlier deadline refuses instead of extending authority. After resolution, `revalidateFacts` receives frozen `terminalAuthority={terminal,notAfterMS}` at commit; its initial pre-mutation call receives null. The service rechecks canonical persona status/generation and origin at commit, and the trusted hook must recheck the immutable metadata and every controller/GuestLive/credential/lease/read-policy dependency on the same connection. The receipt gateway's final fresh clock check covers its prepared minimum. These are mandatory production hooks, not a claim that the synthetic fixture supplies real auth/privacy.

A missing event yields the reducer's durable `not_found`. A retained event with scrubbed actor metadata or withdrawn persona throws `unauthorized`; missing key metadata, malformed compact payload, undeclared scopes, mismatched resolver bindings or unavailable resolver throws `unavailable`. No new receipt/domain changes commit in these thrown cases, and no request/member/grant is reopened. A different install's cancel returns `not_found` under the unchanged reducer. Historical admitted leases stay historical after Leave/rejoin. Equal-body receipt replay skips both resolvers and all writes, but Root's receipt `lockAuthorization.revalidate` must independently authorize the saved redacted read **before hash conflict disclosure**, including after privacy withdrawal; a replay never recreates authority or current membership.

## Atomic state, winning authority and reservations

Room state uses separate `state.admission` and bounded `state.admissionStore` metadata. Other room state is preserved. The service maintains host/invite/settings/privacy mirrors, global state/session revisions, event watermark, semantic counters and its own reserved event/receipt shares, without consuming another component's reservations. Local admission revisions remain independent from global room revisions. Room privacy references exactly mirror current retained members/pending rows; terminal references use the indexed event actor fields. All grant writes use generation/ID/key-version CAS under held host policy locks. A changed grant/policy aborts the entire membership+terminal+receipt transaction.

Each pending request reserves **three semantic events** (terminal, possible joined, eventual Leave) and **two receipts** (decision, eventual Leave). Each active guest reserves one Leave event/receipt. One End receipt remains reserved; End's independent event flag and 8,192-byte reservation remain untouched. Approval transfers pending allowances to committed terminal/join events and the new member's Leave allowance. Deny/cancel/expiry releases the unused join/Leave part. Internal batched expiry consumes one owned terminal receipt and releases the rest. Existing unrelated reservations are preserved. Counter-saturated tests commit approval then Leave at 20,000 semantic events and 30,000 committed+reserved receipts, retaining End's receipt/event/bytes. Misc settings/Forget changes share a bounded 1,000 counter. Same-body retry consumes none of these allowances.

Before **every accepted positive creation/request/approval/settings/Forget**, the service checks a worst closed lifecycle postimage. It copies the actual admission state, changes all guest members to removed with maximum safe-integer lease/timestamp widths, expands local mutation/membership/timestamp widths, and retains every pending row (expiry can only shrink them). SQL measures `octet_length(jsonb::text)` for this postimage, then the approved reducer hydrator independently checks it. This upper-bounds every combination of Leave/removal and pending terminal settlement for the admitted state. Further rejoin/approval/settings must reserve again. Global room state/session revisions and grant generation retain terminal increment headroom too.

The admission postimage must fit **16,384 bytes**; its fixed metadata <=4,096 bytes; the entire surrounding room with the worst admission postimage must remain <=262,144−8,192 bytes. No visit/occurrence envelope is borrowed or identity truncated. This component preserves Root's other slice reservations; it does not qualify their separate encoders. Capacity refusal occurs before committing positive work. A later Leave is not allowed to discover that an accepted title consumed its terminal bytes.

The exact regression starts with 25 realistic synthetic members at **16,072 bytes**. The approved pure reducer accepts a 320-byte title producing **16,379**, whose later Leave/removal would produce **16,386/16,389** and refuse. The SQL service rejects the title and retains the original room/events/outbox/receipt state; Leave then commits. Separate fixtures construct all 25 members through the service and remove all 24 guests, or commit all 24 captured-lease Guest Leaves at semantic/receipt saturation, successfully. An additional privacy-withdrawal fixture closes all 24 guests sequentially at saturation, and proves that a previously closed withdrawn member cannot block another guest's reserved Leave or regain membership/terminal authority. A deliberately inconsistent stale-pending fixture proves that a retained scrubbed event UUID rejects a second winner at the unique constraint and rolls back membership/grant/receipt changes. These serialized fixtures are not real PostgreSQL contention evidence. Another proves that surrounding executor bytes cannot consume the 8-KiB End reserve. These are logical byte/reservation checks, not measured native or production performance.

The same transaction persists the slice, scalar mirrors, grant CAS/cooldown, winner events, receipt and outbox, or none. Terminal event IDs are request IDs and losers use one exact unique-index lookup, with room/environment rechecked. A 300-outcome fixture confirms no terminal JSON array and an indexed plan after ANALYZE; this is bounded embedded-engine plan evidence, not production latency/IO qualification. Winner authority retains the original admitted lease even after Leave/rejoin and is never promoted to a current membership.

Outbox writes are content-free and bounded: one coalesced wake marker, one immutable room-expiry job, and at most one coalesced earliest-pending-admission-expiry job per room. State/receipt and those rows commit together. Rearming increments the outbox claim epoch and clears old claim fields; Root's consumer must fence old claims by that epoch. The scope discriminator is `room` or `admissions` on `room_expiry` payloads. No publisher, claim loop or external execution runs here. Ordinary no-change commands still have bounded receipts; exact retries bypass all outbox work.

## Explicit remaining boundaries and adapter requirements

The existing receipt gateway rejects every new mutation when `nowMS >= rooms.expires_at_ms`, including internal admission expiry. The focused test pins that behavior and the previously scheduled room-expiry job. **Root's End/fencing transaction must settle the final clipped pending admissions at room expiry**, use the same winner representation and owned reservations, close participation and retain output guards. This worker does not bypass the gateway, call an expired room active, supply an End reducer or claim an operational expiry worker. Until Root composes that boundary, autonomous room expiry remains unavailable. Before expiry, the internal admission sweep is executable and atomically reserved.

The existing redacted receipt format cannot return full admission/member/lease summaries. It returns the durable admission UUID and revision watermark; Root must add an independently current-authorized projection/lookup in its later adapter. Never encode winner status in a count or return private internal authority as an unrestricted DTO. An old admitted result is historical, and cannot supply current room rights. Persist intention command/ticket/Leave lease IDs before send, retry the same semantic body on ambiguity, and obtain current membership from its authorized read. Leave's durable receipt acknowledges closure, not provider Release or a local playback grant.

Root still owns production current-auth and privacy hooks, all controller/GuestLive and account lifecycle writers, real profile/consent resolution, resolve-ticket verification and pair-key continuity, distributed antiabuse, exact known-scope discovery/locks, authority ownership and cooperating writer gates, indexed privacy redaction/retention, End/room expiry, event projections, outbox claim/publishing, shared wire/schema/HTTP/app adaptation, full hermetic gate, real PostgreSQL concurrent barriers/roles/load, publication and deployment. Missing any needed authority/configuration returns unavailable; structural service boundaries are **not credential privacy proof**. Nothing enables a capability or supports live parity claims.
