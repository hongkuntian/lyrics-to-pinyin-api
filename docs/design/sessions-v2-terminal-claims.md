## Surface and authority

`createTerminalClaims({db, coordinatorEnvironment})` is an internal constructor. It performs no IO and returns a frozen object with exactly:

- `claimNext()` — select at most one due/expired `authority_terminal` row in the configured coordinator namespace, then claim it or retain it as dead debt. Return an opaque handle only after claim COMMIT. Return `null` when no eligible row exists or this one selected row became dead. A caller must not treat null as a proof that the queue or selector range is complete.
- `failClaim(handle)` — separately settle that exact committed claim as a genuine failed attempt. Return frozen `{status:'pending'}` or `{status:'dead'}` after COMMIT. The method accepts no time, transaction, evidence object, SQL, selector, result, source callback or semantic postimage.

The handle is empty, null-prototype and frozen, with all evidence in a closure-owned WeakMap. Reconstructed objects, SQL rows, spreads, proxies of a handle and a handle issued by another store do not carry its brand. No public inspection, renewal, success, refund, mark-success, repair, source producer or End API exists. A lost process/handle leaves its committed debit recoverable only through lease expiry. A failed transaction does not consume the handle; a committed failure removes its brand. A duplicated in-flight failure still races on the full SQL envelope, so only one can settle.

A claim proves only work exclusivity. The row codec and account INSERT privileges do not establish that a credential closed, an installation generation advanced, a private transfer happened, a room ended, an account authenticated, audio may execute or Release holds. This slice never reads or writes those sources. The future source producer must capture and authenticate actual negative source transitions in its own transaction. The future semantic store must reacquire complete earlier source/guard/persona/grant/room scopes, validate actual outcomes and compose its atomic refund with this claim identity. It cannot use a caller callback or a reconstructed handle as evidence. That later composition requires an explicit internal extension; this module exposes no unpacking or positive callback seam.

## Transaction identity and lock order

Root supplies the existing `api/utils/song-library/database.js` abstraction. Its `transaction(fn)` acquires one pg client, runs BEGIN, awaits the callback, runs COMMIT, rolls back on rejection and releases in finally. This store captures the actual transaction method at construction and accepts no externally held client. Calling it from within an account/room transaction is unsupported: it is a separately owned outbox-only transaction, never a same-transaction hook. Constructor dependency injection is a trusted composition boundary, not a public SQL execution API. A deployed pool/catalog/role fingerprint is still a separate qualification obligation.

Each operation captures `txid_current()::text` on its private client before its final write. Claim evidence is installed in the private map only after the wrapper's COMMIT resolves. Failure must run in a different transaction XID through that same captured store/database binding. Neither the XID nor the row envelope is exposed as reusable evidence. Query-result wrappers are decoded synchronously into a fresh frozen tree and the original raw string before the next await; mutable driver result aliases cannot change captured evidence.

Claim selects only outbox rows, using `LIMIT 1 FOR UPDATE OF o SKIP LOCKED`, ordered by due time and job UUID in one fixed environment. It holds no source, user, token, key, guard, persona, grant or room lock, and releases the outbox transaction before returning work. Failure uses one final conditional outbox UPDATE. It never obtains an earlier-category lock while holding an outbox lock. A future semantic transaction must acquire all earlier locks before its job-last CAS, rather than call these methods inside that transaction.

## Exact envelope, clocks and accounting

Selection/RETURNING capture `to_jsonb(outbox_row)::text`. Both final UPDATEs use environment + exact job UUID + closed kind + **entire JSONB row equality** against that original raw envelope. The captured fields are environment, job ID/key/kind, every NULL reference, exact complete payload (selector, cutoff, phase, cursor and optional repair lineage), state, expected count, epoch, nonce/hash/lease, original created/due/retry values, and observed completion/delete fields. JSONB object-key order is immaterial; values and array order are exact. Safe-uint decoding happens before use. Unknown columns or unsupported shapes refuse without mutation; no numeric rounding or JS re-encoding supplies the SQL CAS value.

The last SQL mutation in each transaction owns a fresh MATERIALIZED `clock_timestamp()` numeric sample. Exact numeric comparisons decide due selection, expiry, retry deadline and the final new-lease predicate. Only stored millisecond timestamps are floored. A clock or alias captured earlier in the transaction cannot authorize a late write. The 034 trigger performs its additional actual-clock validation; a boundary crossing between statement and trigger can refuse/roll back. SQL does not promise that the clock cannot cross during COMMIT.

| State at the final exact SQL predicate | Result |
| --- | --- |
| Due pending with count <10, time < original retryUntil, epoch < safe-uint maximum | Claimed with count+1, epoch+1 and a fresh cryptographic nonce hash; lease capped at original retryUntil and nominally 30 seconds. |
| Expired claimed with count <10 and time remaining | Its existing debit is already one failure; preserve it and reserve exactly one new debit, epoch+1 and fresh nonce. No separate charge of the old claim. |
| Live claimed, including count10 | Excluded from selection. No killing/stealing/renewing it. Count10 means nine prior failures plus one outstanding debit, available to a future qualified semantic success. |
| Selected pending count10, expired claimed count10, or selected row at original retryUntil | Dead with count/epoch unchanged, nonce/lease cleared, DB-derived completion and deleteAfter=completion+24h. No new debit or refund. |
| Exact current handle fails, whether its lease is still live or already expired | Count and epoch stay unchanged. Clear nonce/lease; pending if count<10 and original retryUntil remains, otherwise dead. Failure has no lease-validity requirement because it never grants success/refund. |
| Old handle after failure, successor claim, changed envelope, published or dead state | Refuse; cannot charge/refund or mutate the successor. |

Failure preserves original due time as well as created/retry and payload. This primitive schedules no backoff or follow-up; runtime scheduling is outside it. Nothing extends the original <=24-hour retry envelope or changes original invalidation/selector/cursor/repair chronology. Dead/published rows are never selected, reopened, repaired or deleted. Non-NULL deleteAfter does not authorize destruction of retained dead responsibility.

Safe-uint epoch exhaustion refuses a new claim with the debt unchanged; it never wraps, resets or spends another debit. A legitimate exhausted/deadline death needs no epoch increment. Unrepresentable completion+24h similarly refuses and rolls back. Full postimage checks also reject a result whose immutable chronology differs from the selected row, even if its standalone SQL shape is valid.

The current privacy lifecycle engine is unchanged. Its cumulative claim charging is not imported into new-family semantic accounting. Shared error handling preserves only sanitized `40001`/`40P01` transaction retry signals; all other errors become `unavailable` with no original cause, SQL or source data. There is exactly one transaction attempt per invocation. The existing DB wrapper and reference privacy claim/failure methods have no store retry loop; no retry loop is added here.
