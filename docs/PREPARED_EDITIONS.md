# Offline prepared editions

Additive song-library actions and exact wire examples are in [the wire contract](prepared-editions-wire-draft.md). Native inspector selectors are in [the manifest contract](prepared-inspector-manifest.md). Listener paths accept only server-owned edition/artifact IDs and exact Apple variants; they never call generation, first-open unlock, source search, Spotify or playback analytics. Existing guest sessions and the 60/minute account read limit remain active. No source grants are inferred from an Apple storefront or curator market. Runtime currently has **no verified territory resolver**, so only explicitly worldwide publications can be served. Territory-specific candidates remain unavailable until an independently accepted server-side evidence source is implemented.

## Offline workflow

All source content, jobs, reviews and resulting bundles go in an owner-only directory outside Git (for example `artifacts/prepared/<campaign>/`). Commands write new outputs exclusively with mode 0600; they never overwrite a receipt. Do not upload these artifacts to static public hosting. The reviewed JSON bundle is a static publication input; production serving is through authenticated, grant-checked DB reads only.

1. `node scripts/prepared-editions.mjs inventory --output <inventory.json>` enumerates all pool identities with visible qualification gaps. This is manifest-only and makes no network calls.
2. Record a trusted spec: `songID`, independent `display:{title,artist,duration}`, `documentVariant`, exact `variants`, `uses:['read','play']`, `rights`, `recordingEvidence`, `parityReference`. Rights include an evidence `reference`, `reviewer`, exact `source:{provider,itemID}`, explicit `acquisition`, `derivatives`, `persistentServing`, `worldwide`, `territories` (ISO uppercase), and `expiresAt`. `acquisitionReview:{reference,selectionRevision,allOrdinaryProviderPathsApproved:true}` must explicitly review every source path of the current ordinary loader before acquisition. Never set these booleans merely because an endpoint works. recordingEvidence additionally binds `documentID`, `sourceHash`, and exact `variants` to its review `reference` and `reviewer`; `timingVerified` and `listeningVerified` must be true only after review. Independent recording review must verify each alias, source edition, full word timing and a listening pass. Preserve attribution and source/provider revision in the document.
3. `… acquire --spec <spec.json> --output <acquired.json>` invokes the current ordinary recording loader with server-owned pool metadata. It refuses absent/expired permissions before network access and checks the returned provider/item scope and optional expectedSourceHash. This is working acquisition, not fixture admission. Network/source instability remains a failure, never a paid fallback.
4. `… plan --input <acquired.json> --stage translations --output <translation-plan.json>` compiles existing translation requests for all five targets. A genuinely identical language serves the original through an explicit UUID identity translation; Chinese script conversion remains a translation unless the source has that exact canonical tag. Current environment direction policy is enforced. Missing directions remain visible gaps for the content-language owner.
5. `… price --input <translation-plan.json> --pilot-usage <usage.json> --output <price.json>` uses measured `{input_tokens,output_tokens}` and configured model rates. It gives exact unique work count, measured estimate and conservative byte/output-token reservation. Do not represent an absent commercial pilot as a measured estimate. Use representative pilot samples per stage/size class when pricing a campaign; retain their provenance. The implementation permits zero automatic retries (the generic engine supports at most two known-safe retries, but production adapters deliberately use zero).
6. Review the exact plan and USD ceiling **before** `… run --spec <acquired.json> --input <translation-plan.json> --review <review.json> --job <checkpoint.json> --database-config-file <owner-config>`. Review fields: `{reviewer,reference,planID,currency:'USD',retryAllowance:0,ceilingMicros}`. Provider key is `OPENAI_API_KEY` in a private environment, never a command argument. The whole approved ceiling is reserved against existing daily/monthly/emergency generation budgets before the first request. Ordinary admission sees that reservation. DB task claims and local fsynced checkpoints prevent duplicate spending across restarts or machines. Unknown outcomes retain the entire budget hold and stop; reconcile manually with provider evidence. Never delete a checkpoint to retry paid work.
7. `… finish-translations --spec <acquired.json> --input <translation-plan.json> --job <checkpoint.json> --output <translations.json>` creates accepted, content-bound UUID revisions. Export the real native inspector manifest `{version,documentID,sourceHash,requests}` using the app worker's native exporter for each offered original/translated occurrence. Identity/redundant translation layers omitted by the real inspector are omitted from help preparation; all five translation revision descriptors remain. `… plan --input <acquired.json> --stage study --translations <translations.json> --native-manifest <native-export.json> --output <study-plan.json>` compiles original source-only contexts plus translated exact-target/revision contexts. All five explanation languages are independent. Use `--provisional` explicitly for an Intl-based pricing enumeration. The CLI otherwise requires `--native-manifest` (legacy `--native-rows` accepts the same request-only object). Provisional rows manifests are rejected by execution, finalization and static publication, even with a pricing review; they never authorize spending.
8. Repeat price/review/run for the exact Study plan. Study review additionally binds `nativeManifestHash` to the manifest artifact ID (SHA-256 of canonical `{kind:'manifest',selector:{},content:manifest}`). Words batch in <=32 nonoverlapping legal selections per occurrence; characters/whole lines are finite singleton actions. There is no optional translation matrix. `… finish-edition --spec <acquired.json> --input <study-plan.json> --translations <translations.json> --job <checkpoint.json> --output <bundle.json>` requires every requested artifact, five target translations, native parity reference and complete measured vocal coverage. No incomplete edition is advertised.
9. `… validate --input <bundle.json>` performs the same publication checks. Coordinate exact wire freeze, permissions, parity/listening and pilot status with Root before promotion. `… publish --input <bundle.json> --database-config-file <owner-config> [--expected-head <global-generation>] [--expected-generation <edition-generation>]` applies an atomic compare-and-swap. First publish expects an empty head; subsequent publish must pin the current global head. Replacing a mapped source withdraws all former overlapping editions in the same transaction. Runtime credentials have SELECT only.
10. `… withdraw --edition-id <id> --generation <current> --database-config-file <owner-config>` advances the publication generation and retains exact-variant tombstones. A previous grant/translation/pool membership never authorizes later reads. `… status --database-config-file <owner-config>` records current generations and budget holds without protected content or credentials.

A SIGKILL leaves a `.lock` file deliberately. Confirm the worker is dead before removing that lock; resume converts a persisted running attempt to unknown, never a provider retry. DB submitted/unknown attempts also prevent replay if local files are lost. Ready results are reusable. There is no listener, cron or HTTP publisher. Withdrawal is observed by online renewal; this backend adds no push notification service.

## Migration and release

Runtime gets SELECT on publication tables, no publication or generation-budget writes. Owner-only config is the existing `~/.config/lyrica/credentials/backend-admin/migration.json`. Run `… migration-plan --database-config-file <owner-config> --output <plan.json>`, review the complete pending name/digest list, then `… migrate --database-config-file <owner-config> --migration-plan <plan.json>`. This uses the existing bounded checksummed migration lock. Keep `LYRICA_LIBRARY_MIGRATE_ON_BUILD=0`; production build verifies 041 before promotion. Roll back code if needed; do not drop tables, generations, tombstones or spend holds.
